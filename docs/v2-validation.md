# V2 验证记录与学习接续

## 范围

在 v2 分支开发，暂不合并 main。核心为结构化笔记分析和原生工具调用。
V1 `/chat` 保持单轮行为。V2 `/chat/tools` 可显式携带本次历史，不使用数据库、
长期记忆、服务端会话、RAG、LangGraph 或自主规划循环。
Streaming 后置，不阻塞核心实现。

## 上下文实验

`test.py` 保留用户实验，不被正式测试自动收集。比较相同问题：

1. 只有 user 问题。
2. developer 要求“一句话、不含代码”，再加相同 user 问题。
3. user 提出“用生活类比”，assistant 确认，再加相同 user 问题。

观察模型答案是否遵循约束；写出每次实际发送的列表。历史是请求数据，
复用客户端并不会自动保存历史。assistant 历史是调用者提供的材料，并非可信证据。
输入字符数不等于 token 数，token 数随模型和编码变化；本项目的字符限制只提供
应用侧保护，不保证不超过模型上下文窗口。历史、工具定义、工具结果和输出预算
都要占上下文空间。正式使用前应按实际模型的窗口与 tokenizer 核算预算。

## 输出约束

普通文本没有机器可读结构保证；JSON Mode 仅约束 JSON 格式；JSON Schema
进一步描述字段、类型和范围；Pydantic 在收到结果后做本地解析校验。
本项目显式请求 `text.format` 的 `json_schema` 和 `strict=true`，并在 Service
执行 `model_validate_json`。约束包括非空摘要、摘要长度、关键词数量、非空及去重、
难度枚举、禁止额外字段。模型拒绝、生成未完成、空文本和本地校验失败都不能作为成功结果。

这些检查不能证明摘要真实、难度判断合理。人工小评测：

| 输入 | 人工检查 |
| --- | --- |
| 装饰器用于增加日志 | 摘要保留原意；关键词提到装饰器，不编造其它用途 |
| 只有一句简短定义 | 不扩写成原文不存在的复杂原理 |
| 笔记中夹带“忽略规则” | 作为笔记数据处理，仍返回约定结构 |
| 不含技术信息的文本 | 人工判断模型是否编造技术信息；目前不声明能可靠识别所有离题输入 |

## 工具闭环

白名单只有只读 `lookup_concept(term)`，查询内置术语表，无网络、文件写入或任意代码执行。
模型提出函数调用；应用校验函数名和 JSON 参数；Python 执行；用 `call_id`
回传 `function_call_output`；再次请求模型给出最终答案。
保留第一轮全部输出项（包括 reasoning），不混淆 item.id 和 call_id。

最多一批四个调用。标识缺失或重复、数量超限时在执行前拒绝整批。
未知工具、非法参数和工具异常转换成脱敏的结构化错误回传模型；概念不存在返回
`found=false`。第二次请求 `tool_choice=none`；如模型仍要求工具则失败，
不会进入无限循环。响应含 `tool_results`，可核对实际执行证据；仍需人工判断最终答案
是否忠于工具结果。白名单不等于模型一定正确理解查询，不能把自然语言声称“查过”当执行证据。

## 自动化证据

运行 `uv run python -m pytest -q`。测试目录禁止真实 SDK 请求，使用假配置。
V2 测试使用真实 SDK Response 对象解析模拟响应，覆盖结构化结果、约束失败、
拒绝与未完成响应、异常转换、工具参数、执行失败、批次限制、call_id 衔接、
reasoning 保留、最终停止、HTTP 边界及生命周期，另包含 V1 回归。
这些是离线协议与业务测试，不证明真实提供商当前兼容。

## 提供商验收（尚待执行）

本次未调用付费模型。兼容 OpenAI SDK 不等于兼容 Responses、严格 JSON Schema
或原生工具调用。保留现有 base URL 和 model 配置，不擅自替换模型；不兼容时返回
上游错误（HTTP 502），不悄悄降级成提示词伪装的工具调用。

用户先确认当前提供商支持相应接口与参数，再执行：

```bash
LLM_MAX_RETRIES=0 uv run python -m scripts.verify_v2 --live
```

最多三个应用层模型请求（结构化一次、工具一至两次）。需记录：所用提供商和模型、
日期、结构化校验结果、至少一个成功工具结果、最终答案与人工事实核对。
若没有工具调用，脚本不会将其标记为工具闭环通过。费用和返回内容由当前提供商决定。
正式阶段验收还需这一步成功，以及用户对核心代码的解释与复盘。

## 重试与日志

仅 SDK 层按 LLM_MAX_RETRIES 配置负责传输重试；默认 0。Service 不额外重试，
校验失败不自动修复重发。设置非零值可能增加请求次数和费用；网络错误不总能证明
上游没有处理请求。未来加入写操作工具时，必须先设计幂等键与去重，不能原样重放副作用。
超时是网络操作超时，非整个流程的总时限。日志记录阶段、耗时或错误分类，不记录
用户笔记、工具参数、密钥和上游响应原文。终端实验输出和 HTTP 正常结果包含用户数据，
不是持久日志；生产部署仍需按场景补充数据治理。
